# Приниматель решений (Telegram-бот)

Бот выбирает один из вариантов пользователя по живым действиям людей:
транзакции биткоина, сделки на бирже, правки Википедии.
Подписка на @kolokotol обязательна для любого действия.

## Запуск на Railway
1. Создай бота в @BotFather, забери токен.
2. Добавь бота админом в канал @kolokotol (без прав, нужен только для проверки подписки).
3. Залей эту папку в GitHub-репозиторий.
4. Railway -> New Project -> Deploy from GitHub repo.
5. В сервисе: Settings -> Region выбери Европу (Binance режет часть американских серверов;
   если всё же заблокирует, бот сам переключится на Coinbase, потом Kraken).
6. Volume: добавь и смонтируй в `/data` (иначе база обнулится при каждом деплое).
7. Variables:
   - `BOT_TOKEN` — токен из BotFather
   - `ADMIN_ID` — твой числовой Telegram ID
   - `DB_PATH` = `/data/decision.db`
   - (по желанию) `DAILY_LIMIT` — по умолчанию 5, `CHANNEL` — по умолчанию @kolokotol
8. После деплоя напиши боту `/sources`: все три источника должны быть 🟢.

## Команды админа
- `/stats` — пользователи, вопросы, нажатия, конверсия отказ -> подписка
- `/export` — CSV с вопросами/ответами и пользователями
- `/sources` — состояние потоков живых событий

## Что где менять
- Все фразы бота: `texts.py`
- Мануал: заменить файл `assets/manual.pdf` (бот сам зальёт новую версию)
- Дневной лимит и границы числа вариантов: `config.py`

## Как считается ответ
Нажатие «бросить» -> бот слушает три потока -> побеждает источник, чьё событие пришло первым ->
берутся ещё 2 события этого источника -> SHA-256 от (номер запроса, время, источник, события)
-> остаток от деления на число вариантов (с отбрасыванием «хвоста», чтобы не было перекоса).
Полная запись каждого броска (источник, события, хэш) лежит в базе и в `/export`.
